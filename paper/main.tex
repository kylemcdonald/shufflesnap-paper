\begin{abstract}
An image atlas gives every item its own grid cell, near where an embedding placed it. Rounding coordinates causes collisions and holes; exact assignment solvers are expensive at scale. ShuffleSnap repeatedly re-matches a few dozen points to a few dozen cells, solving each small problem exactly. At first those cells are far apart, so points can cross the grid; later they are adjacent, refining the layout. On five synthetic families at $40{,}000$ points, median gaps to high-accuracy references are $\StatHeadlineGapLo$--$\StatHeadlineGapHi\%$ in $\StatHeadlineTimeLo$--$\StatHeadlineTimeHi$~s, versus $\StatHeadlineBspotTimeLo$--$\StatHeadlineBspotTimeHi$~s for BSP-OT, which usually achieves lower cost at short, matched runtimes.
\end{abstract}

\section{From a point cloud to a grid}
\label{sec:intro}
A two-dimensional embedding gives every image in a collection a position, with similar images near each other. To show the collection as an atlas, we want a regular grid with one image per cell. Which image goes where?

Rounding each position to its nearest cell fails: crowded regions collide and sparse regions leave holes. We need a one-to-one matching that moves each point as little as possible (Figure~\ref{fig:method}(a)).

We score a matching by total squared displacement. For points $p_1,\ldots,p_n$, cell centers $g_1,\ldots,g_n$, and an assignment $a$ sending point $i$ to cell $a(i)$,
\begin{equation}
  \cost(a)=\sum_{i=1}^{n}\|p_i-g_{a(i)}\|^2.
  \label{eq:objective}
\end{equation}
Points and cell centers stay fixed; only the matching changes. Squaring penalizes large displacements heavily.

Minimizing \eqref{eq:objective} exactly is a linear assignment problem; general-purpose exact solvers grow expensive at hundreds of thousands of points. RasterFairy \cite{klingemann2016} instead recursively splits the points into balanced groups and gives each a block of the grid; BSP-OT \cite{genest2025} merges randomized spatial partitions, keeping cost-lowering swaps. Both are fast, and leave displacement to refine. Linear assignment sorting (LAS/FLAS) \cite{barthel2023} likewise refines grids by re-solving small neighborhoods, but for a feature-space objective rather than a fixed planar target (Appendix~\ref{sec:related}).

ShuffleSnap's contribution is not the small exact solve but how the solves are organized: coarse to fine, with the cells inside one solve first spread widely across the grid and then brought together.

\section{Small assignments at several scales}
\label{sec:method}
\textbf{Step 1: improve a small group of cells.} Start with any valid assignment, by default a seeded random shuffle. Pick a window of grid cells---by default $6{\times}6$, at most $36$ cells---and collect the points \emph{currently assigned} to those cells, not those lying nearby in the input plane. Re-match those points to those same cells exactly, and accept the result only if it lowers their total squared displacement (Figure~\ref{fig:method}(a)). Points only trade cells inside the window, so the assignment stays one-to-one, and every accepted move lowers the global cost \eqref{eq:objective}.

\textbf{Step 2: make the same solve reach farther.} Adjacent cells can only shuffle points among neighbors; a point belonging on the far side of the grid needs a long, easily blocked chain of local moves. Choose a stride $s$ instead and take every $s$-th row and every $s$-th column: still at most $36$ cells and a solve of the same size, but spanning $5s+1$ cells in each direction (Figure~\ref{fig:method}(b)). Only the spacing changes; the assignment stays at full resolution.

\textbf{Step 3: cover the grid.} At stride $s$ the cells fall into $s^2$ interleaved subgrids, and we tile every subgrid with windows. Windows in one tiling share no cells, so their solves run in parallel. To let points cross tiling boundaries, we repeat with the tiling shifted by half a window horizontally, vertically, and diagonally (Figure~\ref{fig:method}(c)). These four tilings make one \emph{round}. Edge windows are clipped (Appendix~\ref{app:method}).

\textbf{Step 4: reduce the stride, then finish locally.} Run one round at a stride large enough for a window to reach across the grid, halve the stride, and repeat down to stride $1$; then keep running stride-$1$ rounds until a full round accepts no move. Coarse rounds settle which region each point belongs in, fine rounds correct the details, and both matter. Appendix~\ref{app:method} gives the exact starting stride, rectangular-grid rule, and stopping tolerance.

For a fully occupied grid and fixed window size, each cell is in at most one window per tiling, so a round takes linear time and memory is linear. The scheduled descent has logarithmically many rounds; we have no practical bound on the number of finishing stride-$1$ rounds, and nothing guarantees a globally optimal result. Each small solve is exact, but the whole algorithm is a heuristic.

On every family ShuffleSnap's median final gap is lower than BSP-OT's, $\StatHeadlineGapLo$--$\StatHeadlineGapHi\%$ against $\StatHeadlineBspotGapLo$--$\StatHeadlineBspotGapHi\%$, but BSP-OT finishes in $\StatHeadlineBspotTimeLo$--$\StatHeadlineBspotTimeHi$~s while ShuffleSnap converges in $\StatHeadlineTimeLo$--$\StatHeadlineTimeHi$~s. Stopped at BSP-OT's runtime instead, ShuffleSnap has the higher median gap on four of five families (Appendix~\ref{sec:bspot}).

The schedule matters, not just the round count: with the same solver, windows, and random start, on the tested meander inputs a stride-$1$-only schedule stalls near a $0.5\%$ gap after hundreds of rounds, while the default finishes below $0.01\%$ in about fifteen (Appendix~\ref{sec:ablations}). Figure~\ref{fig:main-action} shows the progression qualitatively. Scaling to millions of points is in Appendix~\ref{sec:scaling}; an MNIST atlas in Appendix~\ref{sec:mnist}.

ShuffleSnap suits cases where extra refinement time is worth a lower-displacement atlas. It does not repair the embedding or directly optimize semantic neighborhoods. Its accuracy is empirical: five synthetic families and one real embedding, without a global optimality guarantee.

\section{Algorithm, implementation, and scope}
\label{app:method}

\subsection{Specification}
\label{sec:spec}
The inputs are $n$ planar points $p_1,\ldots,p_n$ and $m\ge n$ grid cell centers $g_1,\ldots,g_m$ on a regular lattice. The assignment is stored both ways: $a(i)$ is the cell of point $i$, and an \emph{owner} array gives the point in each cell ($-1$ when empty). Points and cell centers never move; only the matching changes. The objective is \eqref{eq:objective}. Grid centers span $[0,1]$ on each axis; a one-cell axis is centered at $0.5$. The API leaves input coordinates unchanged (Section~\ref{sec:protocol}).

\textbf{Windows.} A window is a block of at most $w\times w$ grid cells, $w=6$ by default. A \emph{window move} collects the points currently assigned to those cells, wherever they lie in the input plane, and re-matches them to the same cells with an exact dense assignment solve on at most $36$ items. The current matching is one candidate, so the solve cannot make things worse; its result is applied only if strictly better.

\textbf{Strides and subgrids.} For a stride $s\ge1$ and offset $(o_r,o_c)$ with $0\le o_r,o_c<s$, the cells at rows $o_r,o_r+s,\ldots$ and columns $o_c,o_c+s,\ldots$ form one \emph{subgrid}. The $s^2$ offsets give $s^2$ interleaved subgrids that cover every cell exactly once. A window at stride $s$ is $w\times w$ subgrid cells, spanning $(w-1)s+1$ rows and columns of the real grid: at $w=6$, one solve can move a point $5s$ cells.

\textbf{Phases and rounds.} A \emph{phase} tiles every subgrid with side-by-side windows starting at a phase offset $\phi\in\{0,3\}$ per axis (in subgrid cells, i.e.\ $3s$ grid cells). Windows in a phase share no cells. On each axis, the first window of a shifted tiling begins at $\min(\phi,\,\ell-1)$ where $\ell$ is the subgrid length, so short subgrids still get one window; no window is created before the axis start, and the last window is clipped to the cells that remain (Section~\ref{sec:boundaries}). The four offset combinations $\{(0,0),(0,3),(3,0),(3,3)\}$ make one \emph{round} at stride $s$.

\textbf{Schedule.} For an axis of $L$ cells the starting stride is the smallest power of two $s_{\max}$ with $w\,s_{\max}\ge L$; this sets a coarse scale and need not produce a window spanning the whole axis. The solver runs one round, halves the stride, and repeats down to $1$, then repeats stride-$1$ rounds until a full round applies no move. Rectangular grids use independent strides per axis (a $50{\times}1000$ grid starts at $(16,256)$), each halving on its own and staying at $1$ once there. Algorithm~\ref{alg:descent} gives the square case.

\textbf{Acceptance and stopping.} A window's result is applied when $\mathrm{old}-\mathrm{new}>10^{-12}\cdot\mathrm{old}$ for that window's cost, which rejects numerical ties. The run stops when a stride-$1$ round applies nothing, or when an optional wall-clock budget expires. The default start is a seeded random permutation (Section~\ref{sec:ablations}).

\begin{algorithm}[t]
\caption{Multiscale window descent (square grid; rectangular grids use one stride per axis)}
\label{alg:descent}
\begin{algorithmic}[1]
\State $a \gets$ any legal assignment \Comment{default: a seeded random permutation}
\State $s \gets$ smallest power of $2$ with $w\,s \ge L$ \Comment{$w=6$; $L$ = grid side}
\Loop
  \State $\mathit{changed} \gets \textbf{false}$
  \For{phase offset $\phi \in \{(0,0), (0,3), (3,0), (3,3)\}$} \Comment{half-window shifts, in subgrid cells}
    \State $W \gets$ all windows of the offset-$\phi$ tilings of all $s^2$ stride-$s$ subgrids \Comment{pairwise disjoint}
    \ForAll{$\omega \in W$ \textbf{in parallel}}
      \State $\mathit{changed}_\omega \gets \textbf{false}$
      \State collect the points assigned to $\omega$'s cells; solve their exact assignment to those cells
      \If{$\mathrm{old} - \mathrm{new} > 10^{-12}\cdot\mathrm{old}$} apply the new matching; $\mathit{changed}_\omega \gets \textbf{true}$
      \EndIf
    \EndFor
    \State $\mathit{changed} \gets \mathit{changed} \lor \bigvee_{\omega} \mathit{changed}_\omega$ \Comment{OR-reduction over workers}
  \EndFor
  \If{$s = 1$ \textbf{and not} $\mathit{changed}$} \Return $a$ \Comment{scheduled-window fixed point}
  \EndIf
  \If{optional time budget exhausted} \Return $a$
  \EndIf
  \State $s \gets \max(1, s/2)$
\EndLoop
\end{algorithmic}
\end{algorithm}

\subsection{Properties}
\label{sec:properties}
Four facts follow directly. \emph{Every intermediate assignment is legal}: a move only permutes points among its own cells. \emph{The global cost strictly decreases} with every applied move: the window's cost is a summand of \eqref{eq:objective} and nothing else changes. \emph{In exact arithmetic the solver terminates}: finitely many assignments, none revisited. \emph{Windows in a phase never conflict}: they touch disjoint cells and hence disjoint points, so they can be solved and applied in parallel and the result does not depend on scheduling.

A converged run is a \emph{scheduled-window fixed point}: none of the four stride-$1$ tilings improves it beyond the tolerance. Other placements, larger windows, or coarse windows might still help. The final gap is measured, not bounded.

Work per round: a window on $k\le w^2$ occupied cells costs $O(k^3)\le O(w^4k)$, and a phase's windows are disjoint so their $k$ sum to at most $n$, giving $O(n\,w^4)$ per phase and per round on a fully occupied grid, at any stride. (Window counts vary with stride and clipping; the bound does not rely on a fixed count.) The initial descent has $O(\log L)$ rounds; $T$ extra stride-$1$ rounds cost $O(T\,n\,w^4)$, and we give no practical bound on $T$. Shell sort and multigrid \cite{shell1959,brandt1977} are analogies for why coarse corrections come first; their analyses do not transfer to this permutation search.

\textbf{Limited reach of adjacent windows.} In one stride-$1$ phase a point moves at most $w-1$ cells per axis, so moving $k$ cells takes at least $\lceil k/[4(w-1)]\rceil$ rounds. This is a lower bound on transport, not an upper bound on convergence: a local fixed point can block the needed exchange entirely. Section~\ref{sec:convergence} measures what happens. Strides address reach; they do not guarantee that the optimum is reachable.

\subsection{Boundaries: keep the clipped trailing window}
\label{sec:boundaries}
Figure~\ref{fig:boundary} shows a seven-cell axis. The unshifted phase creates windows $[0,6)$ and $[6,7)$; the shifted phase creates $[3,7)$, clipped at the edge. That clipped window is the only one joining cell $6$ to cells $0$--$5$. Without it, even a swap between cells $5$ and $6$ could never be repaired by stride-$1$ rounds. The omitted leading half-window $[0,3)$ lies inside $[0,6)$ and would not add a connection across that boundary.

The same situation arises whenever an axis ends in a band of one or two cells after a multiple of $6$ (the $200$-cell benchmark axes: $200=33\cdot6+2$), and independently on any strided subgrid. Keeping the trailing window makes the four-phase round connected on every size of full, unmasked grid; masks can break this (Section~\ref{sec:masks}). Connectivity means improvements \emph{can} propagate, not that a cost-decreasing path to the optimum exists.

\subsection{Rectangular grids, spare cells, and masks}
\label{sec:masks}
When $m>n$, the occupied cells are fixed before optimization. Each window uses only the occupied cells among its own and re-matches their points to those cells, so solves stay square and no point enters an unused cell. The high-level API picks a deterministic occupied subset once; a boolean mask can prescribe the region instead, as in the circular and cut-corner atlases of Figure~\ref{fig:masks}. Which cells to occupy is not optimized. A mask also changes which windows exist and how they connect, so it can affect connectivity, iteration counts, and runtime.

\subsection{Implementation}
\label{sec:impl}
\shufflesnap{}'s kernel is C++ behind a small Python API. Each phase enumerates its windows from two per-axis band tables and chunks them across hardware threads; workers write results into the shared assignment and owner arrays directly, which is safe because a phase's windows are disjoint. The window solver is a fixed-size Jonker--Volgenant routine for at most $36$ items; its local cost matrix and state live on the stack. There is no global cost matrix: window costs are computed from coordinates on demand, so memory is the points, the two index arrays, and the grid axes, $O(n+m)$. Window enumeration for sparse masks depends on $m$. Since scheduling cannot change which moves are applied, a run to convergence is deterministic given inputs and parameters.

By default the solver runs to a scheduled-window fixed point; every ordinary experiment reached one, while the billion-point run (Section~\ref{app:billion}) stopped at its budget. An optional wall-clock budget supports interactive use, and since progress is front-loaded (Section~\ref{sec:scaling}) an early stop usually costs little. An optional \texttt{polish\_all\_offsets} sweep tries every complete $6{\times}6$ placement once. The high-level \texttt{snap\_to\_grid(points)} chooses a near-square grid when none is given (or takes a mask), seeds a deterministic random permutation, runs Algorithm~\ref{alg:descent}, optionally polishes, and returns grid positions, the assignment, and the grid shape. The version used here is ShuffleSnap~0.4.0.dev0, commit \href{https://github.com/kylemcdonald/shufflesnap/tree/afd6626c3353b41c0931a7e5111b31c4b2c3e8f2}{\texttt{afd6626}}. This revision removes the coordinate inset used by PyPI~0.3.0.

\section{Evaluation protocol and comparative results}
\label{sec:eval}

\subsection{Protocol}
\label{sec:protocol}
\textbf{Machine.} One desktop: \StatMachine{}, $\StatThreads$ hardware threads, $\StatMemory$~GB RAM, Linux, C++ at \texttt{-O3}. Descent uses all threads unless stated. Timings are specific to this machine and implementation.

\textbf{Inputs.} Five synthetic families: normalized Gaussian random walks (\emph{meander}, the default), two separated blobs, a ring, a spiral, and a mixture of five unequal Gaussians. Reference-size experiments use $96{\times}96$ ($9{,}216$ points) and $200{\times}200$ ($40{,}000$), instance seeds $\{0,1,2\}$, medians with min--max bands where visible. Stress runs and MNIST are single instances. The initialization ablation uses five random permutations per instance; otherwise initialization is the package's deterministic random permutation unless ablated.

\textbf{Benchmark normalization versus the API.} The benchmark harness rescales each coordinate axis independently to $[0,1]$ before calling any solver. This can change the input's aspect ratio and defines the geometry all methods optimize. The API applies no normalization.

\textbf{Metric.} For an assignment $a$ and reference cost $C_{\mathrm{ref}}$, the \emph{reference gap} is $100\,(\cost(a)/C_{\mathrm{ref}}-1)$ percent.

\textbf{References.} Reference costs come from an on-demand, epsilon-scaled floating-point auction solver with final epsilon $\max(10^{-12}/n,\operatorname{ulp}(C_{\mathrm{scale}}))$, $C_{\mathrm{scale}}=\max(1,\max_{ij}|c_{ij}|)$. In exact arithmetic epsilon-complementary slackness would bound the additive error by $n\varepsilon$; the stored runs have no independently verified dual certificate, so we claim no certified optimality. On $12$ meander instances of $400$--$4{,}096$ points where dense Jonker--Volgenant, SciPy, and the auction all finish, their costs agree within a relative $\StatOracleMaxRelErr$. Cached references cover all five families at $96{\times}96$ and $200{\times}200$ and smaller meander instances used in scaling. Above $40$k points there are no references: those runs report progress relative to their own final cost, and we say whether that cost came from convergence or a budget.

\textbf{Timing rules.} Convergence and scaling traces include initialization where stated. Distribution and ablation tables report the solver's measured descent time, excluding input generation. The BSP-OT driver's time excludes input loading and target-grid construction. The time-matched comparison (Section~\ref{sec:bspot}) excludes input construction and ShuffleSnap's seed and keeps only fully completed round checkpoints, using medians of $3$ instances and $5$ timing repeats (repeats re-time the same input; seeds are independent inputs).

\textbf{Provenance.} Results, figures, and scripts: \url{https://github.com/kylemcdonald/shufflesnap-paper}; solver: \url{https://github.com/kylemcdonald/shufflesnap}. Headline statistics and Table~\ref{tab:bspot} are generated from stored results. Results through $4.2$ million points, including auction references, use this version in unit-square coordinates; \path{benchmarks/results/environment_unit_square.json} records the environment, source hashes, and BSP-OT revision. The $10^8$-point comparison includes raw driver logs. The $10^9$-point comparison retains historical measurements from a custom single-plan port with unequal settings (Section~\ref{app:billion}).

\textbf{The comparator.} BSP-OT \cite{genest2025} builds a bijection between two point sets in loglinear time: it recursively splits both sets into halves of matched size along data-adapted directions until single points pair up, then merges several randomized constructions, keeping cost-decreasing swaps. It targets the same squared-distance objective and the official implementation is parallel C++,\footnote{\url{https://github.com/baptiste-genest/BSP-OT}, header-only release, Gaussian bijective-matching mode; driver \texttt{solvers/cpp/bspot\_grid.cpp}.} tested here with $16$ plans. Both methods use multiple threads on the $24$-thread machine, BSP-OT across plans via OpenMP and ShuffleSnap across windows; BSP-OT's OpenMP limit was $24$ threads.

\textbf{Results.} The two methods sit at different points on the quality--time curve. BSP-OT returns in $\StatHeadlineBspotTimeLo$--$\StatHeadlineBspotTimeHi$~s at $1.4$--$1.9\%$ on three families, $0.09\%$ on two blobs, and $14\%$ on the spiral. ShuffleSnap's converged gaps are $100$--$400\times$ smaller on the typical families but take $\StatHeadlineTimeLo$--$\StatHeadlineTimeHi$~s. The time-matched column is the short-budget comparison: at each instance's BSP-OT time ShuffleSnap has completed only a few coarse rounds, and BSP-OT has the lower median gap on four of five families (meander: $\StatBspotTimeMatchedMeanderGap\%$ versus $\StatBspotMeanderGap\%$). Ring is the exception ($0.49\%$ versus $1.77\%$), and illustrates the sensitivity to timing: BSP-OT takes $0.08$--$0.09$~s on two ring instances, allowing more descent rounds; on the instance taking $0.04$~s, ShuffleSnap's checkpoints are still at $9$--$27\%$. One more completed round can change this column substantially. More plans help BSP-OT only a little ($64$ plans: $\StatBspotSixtyFourGap\%$ on meander at about $\StatBspotSixtyFourTimeRatio\times$ the time). In the scaling sweep, BSP-OT takes $\StatBspotLargestTime$~s at $4.2$ million points while descent reaches within $0.1\%$ of its own converged cost in $\StatLargestWithinTenthS$~s; without references there, this is not a gap comparison.

\textbf{Scope.} BSP-OT handles arbitrary dimensions, partial matchings, and sparse couplings, none of which ShuffleSnap attempts; it usually wins the short-budget comparison in this setting. ShuffleSnap specializes to grid targets, whose regularity is what makes strided tilings cheap.

We embed all $70{,}000$ MNIST digits \cite{lecun1998} with UMAP \cite{mcinnes2018} ($15$ neighbors, min-dist $0.05$, seed $0$) and assign them to a $250{\times}280$ grid, exactly $70{,}000$ cells. From the default random seed, descent \StatMnistConverged{} after $\StatMnistRounds$ rounds in $\StatMnistElapsed$~s (Figure~\ref{fig:mnist-detail}, right). No reference was computed at this size.

A low cost does not by itself show a good picture, so we also measure two neighborhood properties (\texttt{benchmarks/bench\_mnist.py}, $k=10$, self excluded). \emph{Neighborhood preservation} is the mean fraction of a point's $10$ nearest neighbors in the original embedding that are also among its $10$ nearest neighbors in grid position. \emph{Label agreement} is the mean fraction of a point's $10$ nearest neighbors, in whichever positions are being evaluated, that share its digit label. These measure something different from displacement and are read separately.

The converged assignment preserves $\StatMnistKnnFinal\%$ of embedding neighborhoods with $\StatMnistLabelFinal\%$ label agreement, against $\StatMnistLabelEmbed\%$ in the continuous embedding; the random seed alone scores $\StatMnistKnnSeed\%$ preservation (rounded). On the same embedding, RasterFairy preserves $\StatMnistKnnRasterFairy\%$ with $\StatMnistLabelRasterFairy\%$ label agreement but leaves $\StatMnistRasterFairyExcessPct\%$ more squared displacement ($\StatMnistRasterFairyCost$ versus $\StatMnistFinalCost$). BSP-OT leaves $\StatBspotMnistExcessPct\%$ extra cost ($\StatBspotMnistCost$, in $\StatBspotMnistTimeMs$~ms) but preserves $\StatBspotMnistKnn\%$ of neighborhoods with $\StatBspotMnistLabel\%$ label agreement. On this one embedding descent has the lowest cost and the best neighborhood scores of the three; one example is limited evidence about visual quality in general.

\section{Convergence and design choices}
\label{sec:convergence}

Why strides, this schedule, a random start, and $6{\times}6$ windows? The answers are empirical, mostly from $200{\times}200$ meander instances, and are not a full factorial study.

\subsection{How descent progresses}
\label{sec:descent}

\begin{figure}[tbp]
  \centering
  \includegraphics[width=\linewidth]{convergence.png}
  \caption{Gap to the auction reference on $200{\times}200$ meander instances (median of $3$; right panel adds initialization time and a min--max band). Multiscale descent converges to approximately $0.003$--$0.021\%$ in a fraction of a second from either start; the same windows without strides (``local only'') terminate near $0.5$--$0.6\%$ from both local-only starts, including RasterFairy's construction.}
  \label{fig:convergence}
\end{figure}

Figure~\ref{fig:convergence} tracks the reference gap by round; Figure~\ref{fig:main-action} shows the same kind of run as images. From a random permutation (median starting gap around $500\%$), multiscale descent crosses $1\%$ in five rounds, $0.1\%$ in $\StatConvRoundsToTenth$ rounds ($\StatConvRandomTimeToTenthS$~s), and converges at $\StatConvRandomFinal\%$ in $\StatConvRandomElapsed$~s. Structural correction happens in the coarse rounds; the stride-$1$ tail is polishing. A raster-sorted start (gap about $210\%$) follows the same trajectory after one coarse round but ends at a higher median cost here; Section~\ref{sec:ablations} quantifies that.

\textbf{The same windows without strides.} Stride-$1$ rounds alone from the raster start need $\StatConvLocalRoundsToOne$ rounds and $\StatConvLocalTimeToOne$~s just to cross $1\%$, and stop at a scheduled-window fixed point after $\StatConvLocalRoundsFinal$ rounds (medians) at $\StatConvLocalFinal\%$. A lower-cost start still stalls at a similar gap: RasterFairy \cite{klingemann2016}\footnote{We run the released \texttt{rasterfairy} package. Its splits sort integer-cast coordinates, since it expects pixel-scale input, so point clouds are scaled up before the call; its output is unaffected.} begins at $\StatConvRasterFairySeedGap\%$, yet local windows from it stall at $\StatConvRasterFairyLocalFinal\%$. On these inputs, local-only descent reaches worse fixed points from each tested start. These runs change both schedule and start; the schedule ablation below includes a local-only run from the random start and lands in the same place.

\textbf{A structured start can end higher.} Using BSP-OT ($16$ plans) as the initializer on the three $200{\times}200$ meander instances, descent starts at $\StatBspotSeedGap\%$ but converges to a median $\StatBspotSeedFinal\%$, above the $\StatConvRandomFinal\%$ from random starts. Three instances and one schedule do not establish a general ordering; a structured seed may place the search in a different basin before the coarse scales are visited, but we have not tested that.

\subsection{Schedules, starts, window size, and threads}
\label{sec:ablations}

\begin{figure}[tbp]
  \centering
  \includegraphics[width=\linewidth]{ablations.png}
  \caption{Left: window size trades per-round cost against reach; $w{\le}3$ does not reach $0.1\%$ on all instances, and $w \in \{4,5,6\}$ are all reasonable. Right: schedule variants run to convergence ($200{\times}200$, median of $3$). The default and cycled coarse-to-fine schedules give similar, low median gaps; the ablation is empirical, not a necessity result.}
  \label{fig:ablations}
\end{figure}

\textbf{Schedule} (Figure~\ref{fig:ablations}, right; \texttt{benchmarks/bench\_ablations.py}). Cycling the full descent ($64\to1$) four times lowers the gap by less than $0.00002$ percentage points on each meander instance while adding rounds; one descent captures nearly all of the benefit. Dividing the stride by $4$ instead of $2$ ($64,16,4,1$) finishes around $0.08\%$. Half-depth descent ($8,4,2,1$, omitting the coarsest levels), fine-to-coarse, and local-only all finish at $0.4$--$0.6\%$. These motivate the default; they do not prove one descent suffices on every input, or that a stride-$1$ fixed point could not be improved by a later coarse move.

\begin{figure}[tbp]
  \centering
  \includegraphics[width=\linewidth]{init.png}
  \caption{Initialization ablation. Left: converged gap from the raster-sorted seed versus a random permutation on the five families ($200{\times}200$; $3$ instances each, $5$ permutations per instance). Right: rounds to strict convergence on meander instances as the grid grows (median of $3$); the sorted seed's convergence tail stretches with scale while the random seed's does not.}
  \label{fig:init}
\end{figure}

\textbf{Initialization} (Figure~\ref{fig:init}). A random permutation costs $O(n)$ to build and, in this ablation, ends lower than the raster-sorted start. Comparing each raster run against the median of five random permutations of the same instance, the random start converges lower on $\StatInitWins$ of $\StatInitInstances$ family--size--instance pairings (five families at $96{\times}96$ and $200{\times}200$), with a median $\StatInitMedianRatio\times$ lower converged gap ($\StatInitRatioTwoHundred\times$ at $200{\times}200$). The convergence-time difference also appears at larger scales: at $\StatInitLargestSide^2$ ($640$k points; converged costs compared directly, no reference) the raster seed needs $\StatInitRoundsLargestRaster$ rounds ($\StatInitTimeLargestRasterS$~s) to converge where the random seed needs $\StatInitRoundsLargestRandom$ ($\StatInitTimeLargestRandomS$~s), and the random seed ends lower on $\StatInitScaleWins$ of $\StatInitScaleTotal$ instance--size pairs. This is why the default is a deterministic random permutation; it does not mean random is best for every instance or schedule.

\textbf{Window size} (Figure~\ref{fig:ablations}, left). Per-window work grows as $O(w^6)$, but in these measurements larger windows converged lower: $w{=}2$ near $0.3\%$, $w{=}3$ near $0.1\%$, neither reaching $0.1\%$ on every instance; $w\in\{4,5,6\}$ all reach $0.1\%$ in $\StatWindowTimeLo$--$\StatWindowTimeHi$~s, with converged gaps of $0.02\%$ at $w{=}4$ and $0.006\%$ at $w{=}6$. We ship $w=6$, the largest the fixed-size kernel supports.

\textbf{Threads.} Round throughput on $24$ threads is $\StatThreadSpeedup\times$ that on one thread ($512{\times}512$, budgeted runs, so the two settings completed different mixes of coarse and fine rounds). Thread count never changes a run-to-convergence result.

Above $40$k points there are no reference costs (Section~\ref{sec:protocol}); quality below is relative to each run's own final cost.

\subsection{Thousands to millions}

Figure~\ref{fig:scaling} sweeps meander instances from $5$k to $4.2$M points. Against the reference solver the crossover is immediate: at $5$k the auction takes about $5$~s while descent converges in well under a second; at $40$k the auction needs $\StatFortyKOracleS$~s versus $\StatFortyKConvergeS$~s to converge (gap $\StatFortyKGap\%$) and $\StatFortyKToTenthS$~s to reach $0.1\%$. The $10^9$-point run predates this version: points and targets both spanned $[0.03,0.97]$, and the solve was not repeated. The largest run is one instance: a $\StatGigaSide{\times}\StatGigaSide$ grid holding $\StatGigaNBillion$~billion meander points (seed $0$) on the same $\StatMemory$~GB desktop with $24$ threads, under a requested $\StatGigaBudgetH$-hour budget rather than run to a zero-change round, so its quality figures are relative to its cost at the time limit. Behavior extrapolates from Figure~\ref{fig:scaling}: the seed takes $\StatGigaSeedS$~s, each round $\StatGigaPerRoundMin$~minutes, and the run completes $\StatGigaRounds$ rounds. It is within $1\%$ of its final cost after $\StatGigaWithinOneMin$~minutes, $0.1\%$ after $\StatGigaWithinTenthMin$, $0.01\%$ after $\StatGigaWithinHundredthMin$, and $0.001\%$ after $\StatGigaWithinThousandthH$~hours. Peak process memory is $\StatGigaPeakRssGiB$~GiB including coordinates, index arrays, and harness overhead; a dense cost matrix would need $\StatGigaDenseMTiB$~million~TiB.

Figure~\ref{fig:billion-interp} renders the result at $75\%$ interpolation so that places where adjacent cells hold points from distant sources show up as white seams. The seams are sparse and branch along the meander's folds. This is a qualitative view of spatial coherence at a scale where the neighborhood metrics of Section~\ref{sec:mnist} were not computed, and says nothing about the optimality gap.

\textbf{BSP-OT at this scale.} For context we also ran BSP-OT on the same instance, under settings that differ from Table~\ref{tab:bspot}. The official $16$-plan implementation does not fit in $\StatMemory$~GB at $n=10^9$: each matching keeps a plan and its inverse, projection records are $16$-byte pairs, and merging materializes per-point cost vectors, putting one plan near $\StatGigaBspotStockOnePlanGiB$~GiB and $16$ plans beyond $\StatGigaBspotStockDefaultGiB$~GiB (extrapolated from footprints measured at $10^8$). We therefore ported the single-plan Gaussian construction to a memory-lean driver (\texttt{solvers/cpp/bspot\_grid\_giga.cpp}: packed $8$-byte records, streamed slice moments, no inverse plan); at $10^8$ the port's single-plan cost is $\StatHundredMPortDifferencePct\%$ \StatHundredMPortDirection{} the official binary's. At $10^9$ the port builds its bijection in $\StatGigaBspotTimeMin$~minutes on one thread (its parallelism is across plans) with a $\StatGigaBspotPeakRssGiB$~GiB peak, and lands $\StatGigaBspotExcessPct\%$ above descent's final cost; descent, on $24$ threads, drops below that cost by the end of round~$\StatGigaCrossBspotRound$, $\StatGigaCrossBspotMin$~minutes in. Single plans are BSP-OT's weakest configuration. At $10^8$, where the official $16$-plan build fits ($\StatHundredMBspotDefaultGiB$~GiB with four OpenMP threads), $16$ plans land $\StatHundredMBspotSixteenExcessPct\%$ above a descent run from the default permutation with a requested $500$~s budget (last completed round at $\StatHundredMElapsedS$~s), and single plans $\StatHundredMBspotOneExcessLoPct$--$\StatHundredMBspotOneExcessHiPct\%$; raw logs and the upstream revision are retained for this $10^8$ rerun.

These stress tests demonstrate feasibility at $10^8$ and $10^9$ points. With a custom port, one thread against $24$, and a requested time budget rather than convergence, they are not a controlled comparison, and neither billion-point result has a reference cost or an optimality certificate.

\section{Relationship to prior work}
\label{sec:related}

\textbf{Exact and approximate geometric assignment.} Classical exact solvers include the Hungarian method \cite{kuhn1955}, Jonker--Volgenant shortest augmenting paths \cite{jonker1987}, its rectangular variant \cite{crouse2016} used by SciPy \cite{virtanen2020}, and auctions \cite{bertsekas1988}. Geometric algorithms exploit structure a dense matrix hides: Vaidya \cite{vaidya1989}, Raghvendra and Agarwal \cite{raghvendra2020}, and Gattani et al.\ \cite{gattani2023} study matching under Euclidean distance. Those guarantees are for the sum of distances and do not transfer directly to our sum of \emph{squared} distances. For planar RMS matching, which does minimize squared distance, Lahn and Raghvendra \cite{lahn2020} give an $\varepsilon$-approximation in $O(n^{5/4}\operatorname{poly}(\log n,1/\varepsilon))$ time. ShuffleSnap trades such guarantees for a small parallel kernel and measured speed, using a floating-point auction as its reference with the validation in Section~\ref{sec:protocol}.

\textbf{Transport and spatial construction.} Entropic regularization \cite{cuturi2013,flamary2021} scales optimal transport to large problems but returns soft couplings; a bijection needs a further rounding or assignment step. Multiscale transport solvers \cite{merigot2011,schmitzer2016} coarsen the problem, solve it, and refine with hierarchical representations or sparse candidate sets. BSP-OT \cite{genest2025} takes a different route: it constructs a bijection directly by recursively splitting both measures with matched counts and merging randomized constructions, in loglinear time, targeting the same squared-distance objective; Sections~\ref{sec:bspot} and~\ref{app:billion} compare against it. ShuffleSnap keeps every point and grid cell throughout the run, changing the spacing within its search neighborhoods instead of reducing the underlying problem. Every window solve uses the full-resolution coordinates. The resulting local search is simple to parallelize, but we give no approximation guarantee.

\textbf{Grid layouts in visualization.} Snapping embeddings to grids is folklore in the visualization community. RasterFairy \cite{klingemann2016} constructs the assignment top-down by recursive balanced splitting and stops; the result is never refined against \eqref{eq:objective}, and Section~\ref{sec:convergence} measures what that leaves. IsoMatch \cite{fried2015} assigns with a dense solve at small scale. Self-organizing maps \cite{kohonen1990} and kernelized sorting \cite{quadrianto2009} learn grid arrangements from high-dimensional data directly. Closest in spirit, Linear Assignment Sorting (LAS/FLAS) \cite{barthel2023} improves visually sorted grids with local exact assignments over neighborhoods of decreasing radius, and has been parallelized to sort millions of Gaussian-splat parameters \cite{morgenstern2024}; cluster-aware grid layouts \cite{zhou2024} optimize perceptual criteria such as cluster compactness and shape. These methods optimize feature-space or perceptual objectives against evolving target maps. Here the input is already a 2D embedding and the objective is a fixed planar displacement, which is what lets us compare against reference costs for that objective. Balanced and constrained clustering \cite{malinen2014,bradley2000} underlie the exact-cardinality splits that construction methods rely on.

Recent scalable visualization systems solve a different output problem. Sca$^2$Gri \cite{frey2025} selects representative glyphs for a limited grid under displacement constraints; its linear scaling assumes the displayed grid stays much smaller than the input. Here every point keeps its own cell, so targets and output both grow with $n$.
